## 편집 저장 시 바뀌는 부분 (hwpdiff 구조 비교) **[확인]**

### HWP (31개)
- FileHeader, Summary, Script, PrvImage, `_LinkDoc`: **바이트 그대로 유지**.
- BinData: 15개 파일에서 압축 바이트만 다르고 **해제한 내용은 동일**.
- **DocInfo**: 31/31에서 `DOCUMENT_PROPERTIES` 레코드 1개만 바뀜. 캐럿 위치 저장으로 추정 **[미검증]**.
- **BodyText**: 다수 파일에서 수정한 문단의 `PARA_HEADER`/`PARA_TEXT`/`PARA_CHAR_SHAPE` 2–3개 레코드만 바뀜. 일부 파일은 20–135개가 바뀜:
  - 수식이 있는 문서: **모든 `EQEDIT` 레코드 끝에 2바이트(0x0000)가 추가됨**. 수식 스크립트는 동일함. 한컴이 이 바이트를 허용하는지는 **[미검증]**.
  - 수정하지 않은 문단의 `PARA_LINE_SEG` 재계산.
- 비표준 스트림 `PrvText` 추가 1건.

### HWPX (25개) — 손실 위험이 더 큼
- 바뀐 파일: `Contents/section*.xml`, `header.xml`, `content.hpf`, `version.xml`(압축 방식만), `Preview/PrvImage.png`.
- ZIP 항목 **순서 변경** (25/25). `mimetype`의 첫 항목·무압축 규칙은 지켜짐 (25/25).
- section XML 노드의 15–25%가 바뀜:
  - **모든 문단 `id` 재번호** (예: `3121190098` → `0`)
  - 빈 `<t/>` 삽입
- header.xml: `paraPr`의 **명시적 `textDir="LTR"` 속성 제거** 외 다수.
- 본문 텍스트는 재열기 후 전부 일치함. 다만 **원문 XML 보존은 되지 않음**.

## 결론과 다음 작업

1. **무편집 무결성**: 달성. 무결성 계층이 보장하고 테스트로 고정함.
2. **HWP 편집 저장**: 대체로 국소적. 남은 위험은 EQEDIT 2바이트와 LINE_SEG 재계산이며, 한컴 확인이 필요함.
3. **HWPX 편집 저장**: 현재는 rhwp가 XML을 의미 수준으로 다시 씀. 앱은 저장 전에 이 사실을 경고하고 확인을 받음.
   - **다음 단계 최우선 과제**: 원본 section XML에서 수정한 `<hp:p>`만 교체하고 나머지 항목은 압축 바이트까지 그대로 복사하는 **패치 기반 HWPX 저장기**.
4. **한컴독스 검증**: 아직 못 함. 결과 파일을 한컴독스에서 열어 보려면 사용자 로그인과 업로드 승인이 필요함.

## 0.3 추가 (2026-10-27) **[확인]**

- 자동 테스트 30개가 통과했습니다 (core 10, engine 18, app 2). 새로 추가한 테스트가 다루는 내용:
  - 복사·붙여넣기: 서식 유지, 선택 영역 바꾸기, 실행 취소 한 단계
  - 일반 텍스트 붙여넣기: 줄바꿈 → 문단 나누기, 실행 취소하면 미수정 상태로 복귀
  - 입력 전에 지정한 서식이 새로 입력한 글자에만 적용됨 (HWP·HWPX 저장 후에도 유지)
  - 줄 간격·여백·들여쓰기·내어쓰기 값이 HWP·HWPX 저장 후에도 유지됨. 캐럿 위치로 실제 배치를 확인: 들여쓰기 12pt → 첫 줄이 64px 이동, 내어쓰기는 첫 줄이 여백에 그대로 있음
  - 찾기·모두 바꾸기: 대소문자 구분, 실행 취소 한 단계
- 코퍼스 회귀 결과는 이전과 같습니다. 무편집 저장 67/67 바이트 동일, 텍스트·서식·실행 취소 56/56.
- 단위 확인: rhwp의 문단 여백 입력 단위는 HWPUNIT×2입니다(7200 = 0.5인치). 조회 값은 96dpi px이고 소수 첫째 자리까지만 나옵니다. 그래서 pt로 바꾼 뒤 0.1pt 단위로 반올림해 표시합니다.

**[미검증]** 실제 창에서의 조작(클립보드, 찾기 막대, 문단 탭). 리본 화면은 스크린샷으로만 확인했습니다.
